# 工程边界与已知限制

> 本文件如实记录当前系统的能力边界与尚未覆盖的生产级工作，不将单机验证夸大为生产就绪。
> 更新时间：2026-11-24。

## 1. 大模型、引用与流式

| 项目 | 当前状态 | 边界说明 |
| --- | --- | --- |
| DeepSeek 真实调用与流式 | 已通过 `deepseek-chat` 实测问答与 SSE `astream` 逐块流式（首 Token `p50 ≈ 233.5 ms`） | 仅完成小规模评测集验证，未做高并发供应商限流（429）压测与长期成本统计 |
| 无 Key 环境降级 | 未配置 `LLM_API_KEY` / `DEEPSEEK_API_KEY` 时自动采用摘录式回答（`extractive`） | 摘录模式安全可控、零费用，但无法做跨段落归纳整理 |
| 引用支持度校验 | 校验正文中的 `[n]` 落在当次检索证据编号内；越界剔除、完全无引用重试后降级 | 属于**引用结构合法性校验**，未引入句子级 NLI 蕴含模型，不能宣称彻底消除语义幻觉 |
| 多轮指代改写 | 仅基于规则识别指代信号并拼接最近用户原话（自动剥离「旧版本」追问中的旧版本号） | 不支持复杂跨主题省略或超长多轮摘要压缩 |
| 重排模块（Reranker） | 已接入可选 `CrossEncoder`（`app/services/reranker.py`），默认 `RERANK_ENABLED=false` | 当前知识库体量下混合检索已满足区分度，默认关闭以控制本地 CPU 延迟 |

## 2. 检索与知识库同步

| 限制 | 说明 |
| --- | --- |
| 哈希模式定位 | `EMBEDDING_BACKEND=hash`（512 维哈希 + jieba/IDF）仅用于零外部依赖的快速启动与 CI 回归，不等同于深度语义检索 |
| BGE-M3 本地推理开销 | CPU 环境下单次检索耗时约 210–240 ms，生产场景建议部署于独立 GPU 推理服务 |
| 切换后端需显式重建 | 切换 `hash` 与 `bge_m3` 或启用 `milvus` 后，须运行 `scripts/reindex_embeddings.py` 重建索引，暂无异步任务队列自动迁移 |
| 单 Collection 逻辑隔离 | Milvus 采用单 Collection + `expr` 标量过滤 + 业务库按主键二次复核，未按大客户拆分物理 Collection |
| PDF 解析范围 | 仅提取含文本层的 PDF；纯扫描图片版 PDF 会明确报错拦截，未集成 OCR 服务 |

## 3. 工单事务、数据库与安全

| 限制 | 说明 |
| --- | --- |
| PostgreSQL 验证范围 | 已在本地 PostgreSQL 15.20 隔离 schema 验证建表迁移、Savepoint 冲突恢复、`ticket_sequences` 原子取号与并发确认竞争；未做连接池极限压测与主从故障切换演练 |
| SQLite 默认库限制 | 默认 SQLite 便于本地一键演示，但受限于单写锁，多进程生产环境应切换 PostgreSQL |
| 轻量迁移机制 | 使用自研 `schema_migrations` 管理已知版本演进并保留历史数据，复杂生产库演进建议迁移至 Alembic |
| 外部系统协同 | 仅管理支持工单生命周期，未直连真实税局数字账户专线、企业微信/飞书消息推送或真实银行资金前置机 |
| 公网安全防护 | 仅面向本地 `127.0.0.1` 演示，未配置 HTTPS、API 速率限制（Rate Limit）、附件病毒扫描与 WAF |

## 4. 评测口径边界

- `eval/test_cases.json` 中的 40 条样例由开发者围绕财税费控典型场景编写，用于回归验证权限边界、乐观锁确认协议与检索链路，不能替代真实企业工单分布与人工双盲评分。
